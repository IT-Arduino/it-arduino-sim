# Компоненты: как включать, выключать и добавлять

Документ форка «IT-Arduino Симулятор». Апстримовское описание архитектуры
компонентов лежит рядом, в внутреннее устройство детали описано в апстриме, — оно про то, как деталь
устроена внутри. Этот файл про то, как администратору управлять набором
деталей и как добавить новую.

---

## 1. Быстро: убрать или вернуть деталь

Файл `frontend/public/components-config.json`. Он раздаётся как обычная
статика и читается браузером при каждой загрузке страницы, поэтому
**пересобирать образ не нужно** — поправили, обновили вкладку, увидели
результат.

```json
{
  "disabled": [
    "epaper-1in54-bw",
    "gps-neo6m"
  ],
  "enabledOnly": null
}
```

| Поле | Что делает |
| --- | --- |
| `disabled` | Массив идентификаторов деталей, которые скрыть из палитры |
| `enabledOnly` | `null` — показывать всё, кроме `disabled`. Массив идентификаторов — показывать **только** их |

Ключи, начинающиеся с подчёркивания (`_readme`, `_disabled_help`), — подсказки
для человека, код их не читает.

**Убрать деталь:** добавьте её идентификатор в `disabled`.
**Вернуть деталь:** уберите строку из `disabled`.

**Собрать набор для занятия.** Когда на уроке нужен десяток деталей, а не
полторы сотни, заполните `enabledOnly`:

```json
{
  "disabled": [],
  "enabledOnly": [
    "arduino-uno",
    "breadboard",
    "led",
    "resistor-220",
    "pushbutton",
    "potentiometer",
    "buzzer"
  ]
}
```

Если деталь попала в оба списка, она скрыта: «выключено» всегда сильнее.

Порядок применения такой: сначала снимаются детали удалённых плат (см. раздел
4), затем `enabledOnly`, затем `disabled`.

### Если файл сломан

Битый JSON, недоступный файл, `disabled` не массивом — каталог показывается
целиком, а причина уходит в консоль браузера с префиксом `[catalog]`.
Опечатка в конфиге не может обрушить палитру. Отсутствие файла — законная
конфигурация, а не ошибка: сообщения не будет.

Идентификатор, которого нет среди деталей, просто ни на что не влияет.
Проверять его на существование намеренно никто не будет — иначе переименование
детали в апстриме ломало бы конфиг.

## 2. Где взять идентификаторы

Идентификатор — это поле `id` в `frontend/public/components-metadata.json`.
Полный список одной командой:

```bash
node -e "require('./frontend/public/components-metadata.json').components.forEach(c=>console.log(c.category+'\t'+c.id+'\t'+c.name))" | sort
```

Идентификаторы стабильные: они же попадают в сохранённые схемы `.vlx`.
Переименовывать их нельзя — сломаются уже сохранённые проекты.

---

## 3. Что происходит со схемой, где есть выключенная деталь

Выключение убирает деталь **из палитры**, а не из симулятора. Схема, которую
пользователь сохранил раньше, продолжает открываться и работать: код детали
остаётся в сборке. Это сделано намеренно — иначе снятие детали с занятия
ломало бы чужие сохранённые работы.

---

## 4. Чего конфигом не вернуть

Детали, привязанные к платам, которых в форке нет, снимаются жёстко и
`components-config.json` их не поднимет. Список — в
`frontend/src/lib/boardAllowlist.ts`, константа `BOARD_COMPONENT_IDS_TO_DROP`:

| Идентификатор | Что это |
| --- | --- |
| `esp32-devkit-v1` | плата ESP32 |
| `nano-rp2040-connect` | плата RP2040 |
| `franzininho` | плата Franzininho DIY |
| `raspberry-pi-zero`, `raspberry-pi-1`, `raspberry-pi-2`, `raspberry-pi-3`, `raspberry-pi-4`, `raspberry-pi-5` | платы Raspberry Pi |

Причина простая: их процессоры форк не эмулирует. Такая плата на холсте — это
не выбор, а сломанная деталь.

## 5. Как добавить новую деталь

Детали приходят из пакета `@wokwi/elements` (веб-компоненты) плюс собственные
элементы в `frontend/src/velxio-elements/`. Метаданные для палитры собирает
скрипт `scripts/generate-component-metadata.ts`, который сканирует исходники
и складывает результат в `frontend/public/components-metadata.json`.

### 5.1. Деталь уже есть в @wokwi/elements

Чаще всего именно так: пакет содержит больше деталей, чем показывает палитра.

1. Откройте `scripts/generate-component-metadata.ts` и добавьте деталь в
   `CATEGORY_MAP`: ключ — идентификатор детали, значение — категория из
   `frontend/src/types/component-metadata.ts` (`sensors`, `displays`, `input`,
   `output`, `motors`, `communication`, `passive`, `logic`, `analog`,
   `electromech`, `boards`, `other`). Без записи в этой таблице деталь
   попадёт в `other`.
2. Перегенерируйте метаданные:
   ```bash
   cd frontend && npm run generate:metadata
   ```
3. Перегенерируйте картинки для палитры:
   ```bash
   cd frontend && npm run generate:component-svgs
   ```
4. Убедитесь, что деталь не значится в `disabled` в
   `components-config.json`.
5. Проверьте в браузере: деталь появилась в палитре, ставится на холст,
   выводы подписаны.

Шаги 2 и 3 входят в `npm run dev` и в сборку образа, так что при разработке
их обычно достаточно один раз запустить вручную и посмотреть на результат.

### 5.2. Своя деталь, которой в @wokwi/elements нет

1. Напишите веб-компонент в `frontend/src/velxio-elements/` по образцу
   соседних (`inductor-element.ts` — самый короткий пример) и
   зарегистрируйте его в `frontend/src/velxio-elements/index.ts`.
2. Опишите выводы в геттере `pinInfo` — по ним симулятор строит соединения.
3. Если детали нужно поведение во время симуляции (а не только внешний вид),
   её модель живёт в `frontend/src/simulation/parts/`. **Внимание:** каталог
   `frontend/src/simulation/` — ядро апстрима, наши правки там становятся
   вечными конфликтами при обновлении. Прежде чем туда лезть, обсудите с
   командой.
4. Дальше как в 5.1: категория в `CATEGORY_MAP`, перегенерация, проверка.

### 5.3. Своя микросхема без правки кода симулятора

Если нужна не деталь, а именно микросхема со своей логикой, есть встроенная
возможность: **Custom Chip** — вы пишете чип на C, он компилируется в
WebAssembly и работает на холсте. Правки исходников симулятора не требуются.
Описание — в документации апстрима (docs/CUSTOM_CHIPS.md в его репозитории).

В образе `Dockerfile.avr` тулчейн WASI-SDK не поставляется (около 250 МБ, в
апстримовском образе его тоже не было). Чтобы включить компиляцию чипов,
смонтируйте установленный WASI-SDK в контейнер и укажите путь переменной
окружения `WASI_SDK`. Без него эндпоинт честно отвечает, что тулчейн
недоступен, и больше ничего не ломается.

## 6. Где что лежит

| Путь | Роль |
| --- | --- |
| `frontend/public/components-config.json` | Что показывать. Правит администратор, без пересборки |
| `frontend/public/components-metadata.json` | Что вообще существует. Генерируется, руками не править |
| `frontend/src/lib/componentCatalog.ts` | Загружает конфиг и применяет фильтр |
| `frontend/src/lib/boardAllowlist.ts` | Четыре платы форка и жёсткий список снятых деталей |
| `scripts/generate-component-metadata.ts` | Сканирует исходники деталей, строит метаданные |
| `frontend/src/velxio-elements/` | Веб-компоненты деталей |
